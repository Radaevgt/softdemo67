# Бот в мессенджере MAX

Упрощённая версия портала: сотрудник открывает бота, нажимает «Завести дело», вводит сведения об
объекте, проходит тот же опрос и получает справку со сценарием, способом и порядком действий.

Бот `@gorkytech_dev_bot`.

## Что он умеет и чего не умеет

| | |
|---|---|
| Матрица сценариев | Та же, что в портале: 61 сценарий из ТЗ. Бот **не копирует** правила, а импортирует движок |
| Опрос | Тот же адаптивный: прописка не спрашивается для нежилого, наследники — только если правообладатель не жив |
| Несколько состояний | Поддерживаются: объект бывает одновременно бесхозяйным и ФПО, справка тогда содержит оба сценария |
| Справка | Сжатая выжимка в чат + файл (PDF, в запасе .docx) |
| Хранение | **Никакого.** Состояние диалога живёт в памяти процесса |
| База данных | **Не нужна вообще** — ни PostgreSQL, ни SQLite |

Следствие отказа от хранения (решение заказчика): перезапуск процесса теряет недозаполненные
дела. Опрос короткий, повторное прохождение занимает минуту.

## Запуск

Локально, из каталога `backend`:

```bash
BOT_MAX_TOKEN=<токен> python -m bot
```

Токен выдаёт `@MasterBot` в самом мессенджере. Без переменной бот не стартует и скажет об этом.

### Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `BOT_MAX_TOKEN` | — | **Обязательна.** Токен бота |
| `BOT_API_BASE` | `https://platform-api2.max.ru` | Адрес платформы |
| `BOT_POLL_TIMEOUT` | `90` | Длинный опрос, до 90 секунд |
| `BOT_POLL_LIMIT` | `100` | Событий за раз, до 1000 |
| `BOT_SKIP_BACKLOG` | `true` | Пропустить накопленную очередь при старте |
| `BOT_SESSION_TTL_MINUTES` | `60` | Через сколько забыть брошенный диалог |
| `BOT_LOG_LEVEL` | `INFO` | `DEBUG` дополнительно пишет адреса объектов |

## Развёртывание

Отдельной службой из того же образа, что и портал: `COPY backend/ ./` уже забирает каталог
`bot/`, а нужные боту `python-docx`, `reportlab`, `httpx` и шрифт `fonts-dejavu-core` в образе
есть. Менять `Dockerfile` не требуется.

Команда запуска службы: `python -m bot`.

База данных боту не нужна — не привязывайте `DATABASE_URL`, проверку состояния не настраивайте:
бот не слушает порт.

> **Ровно одна реплика.** Маркер событий один на бота: две копии поделят события между собой и
> разорвут каждый диалог пополам. Автомасштабирование отключить.

## Грабли MAX, на которые уже наступили

Каждая из них стоила времени — не открывайте заново.

**Токен идёт без `Bearer`.** Заголовок ровно `Authorization: <токен>`. С префиксом платформа
отвечает 401, хотя токен верный. Передача токена в параметре запроса больше не поддерживается.

**Личный диалог адресуется `user_id`, а не `chat_id`.** `GET /chats` возвращает только групповые
чаты, а отправка по `chat_id` в личке даёт `404 chat.not.found`.

**Корня Минцифры нет в наборе certifi.** Цепочка `*.max.ru` ← `Russian Trusted Sub CA` ←
`Russian Trusted Root CA`. Проверено: с одним certifi запрос падает с
`CERTIFICATE_VERIFY_FAILED`, с приложенным корнем проходит. Корень лежит в
`backend/bot/certs/`, его отпечаток закреплён тестом. Отключать проверку нельзя — в каждом
запросе уходит токен.

**Сообщение — не длиннее 4000 символов**, и не более двух сообщений в секунду в один диалог.
Порядок действий по одному способу бывает до 25 шагов, поэтому в чат уходит выжимка, а полный
текст — файлом. Тест прогоняет все 61 сценарий и следит, чтобы выжимка укладывалась в лимит.

**Файл отправляется в три приёма:** `POST /uploads?type=file` → загрузка на выданный адрес полем
формы `data` → полученный токен во вложении сообщения. **Между загрузкой и отправкой нужна
пауза:** платформа ещё обрабатывает файл и отвечает `400 attachment.not.ready`. В живом запуске
отправка шла через 150 мс после загрузки и падала каждый раз.

**Часть отказов с кодом 4xx — временные**, и обычная проверка «повторять только 429 и 5xx» их не
ловит. Клиент различает их по коду ошибки и повторяет с нарастающей паузой:
`attachment.not.ready` (файл ещё обрабатывается) и `chat.denied` (диалог не успел появиться сразу
после открытия бота — первые одна-две отправки отвергаются, следующая проходит).

**В событии о нажатии кнопки `message` — это сообщение, отправленное ботом.** Собеседника надо
брать из `callback.user`, иначе получится идентификатор самого бота и ответ упрётся в
`403 chat.denied`. По той же причине не годится `message.recipient`: в личном диалоге получатель
входящего сообщения — бот. Клиент дополнительно отказывается отправлять сообщение самому себе,
чтобы такая ошибка называлась своим именем, а не выглядела отказом доступа.

**`/answers` — это не уведомление, а ответ на нажатие**, и он требует ровно одно из двух полей:
`message` (заменяет сообщение с кнопкой) или `notification` (всплывающая подсказка; в
документации не описан, но работает). Пустое тело даёт
`400 proto.payload: Invalid request. \`message\` or \`notification\``. Бот использует замену
сообщения — так перерисовывается клавиатура мультивыбора и не растёт переписка.

**Длинный опрос вместо webhook.** Подписка на webhook сама отваливается через 8 часов без
успешных ответов, а регистрация нового адреса не заменяет старый — копятся дубликаты и события
приходят по нескольку раз. Для одного бота длинный опрос проще и предсказуемее.

## Устройство

```
backend/bot/
  config.py      настройки и отказ без токена
  tls.py         контекст TLS: certifi + корень Минцифры
  certs/         корневой сертификат и его происхождение
  transport.py   клиент MAX: события, сообщения, загрузка файлов
  session.py     состояние разговора в памяти
  texts.py       все формулировки
  keyboards.py   клавиатуры и разбор нажатий
  flow.py        логика разговора — чистая функция
  decide.py      определение сценария без базы
  spravka.py     выжимка в чат и файл
  runner.py      цикл опроса
```

Правило, которое держит всю конструкцию: бот импортирует `app.engine`, `app.enums`, `app.seed` и
`app.documents`, но **никогда** `app.db`, `app.models` и `app.services`. Оно проверяется тестом
`tests/test_bot_isolation.py` — подпроцессом, с вычищенными переменными базы.

## Защита от двойных нажатий

Две независимые:

1. Идентификатор события запоминается — повторная доставка не сдвигает опрос дважды.
2. В каждой кнопке зашит токен шага, новый на каждый вопрос. Нажатие на кнопку из прокрученного
   вверх старого сообщения приходит со старым токеном — бот отвечает «Эта кнопка устарела» и
   повторяет текущий вопрос. Идентификатор события этот случай не ловит.

## Безопасность

Токен хранится только в переменной окружения и не попадает ни в репозиторий, ни в журнал.
Адреса объектов — персональные данные: в журнал пишутся только на уровне `DEBUG`.

> Токен, выданный для разработки, передавался в переписке. Перед продуктивным использованием его
> следует перевыпустить в `@MasterBot`.
