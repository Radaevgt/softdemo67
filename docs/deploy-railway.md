# Развёртывание на Railway

Портал разворачивается одной службой: FastAPI отдаёт и API, и собранный фронтенд. Отдельный
веб-сервер не нужен, CORS не требуется — всё приходит с одного домена.

## Что понадобится

- проект в Railway;
- плагин PostgreSQL в том же проекте;
- этот репозиторий, подключённый к службе.

## Порядок

### 1. Создать службу из репозитория

New → Deploy from GitHub repo → выбрать репозиторий. Railway найдёт `railway.toml` и соберёт
образ по корневому `Dockerfile`. Настраивать команду сборки или запуска вручную не нужно.

### 2. Добавить базу данных

New → Database → PostgreSQL, в том же проекте. Railway подставит в службу переменную
`DATABASE_URL`. Приложение читает её само и приводит к драйверу `psycopg` — строку
`postgres://…` и `postgresql://…` понимает обе.

Если база не видна службе, привяжите её в Variables: `DATABASE_URL = ${{Postgres.DATABASE_URL}}`.

### 3. Задать переменные окружения

Обязательны две. **Без них приложение не поднимется — и это сделано намеренно:**
портал фиксирует авторство решений, поэтому ключ подписи токенов по умолчанию означал бы
доступ к чужим решениям.

| Переменная | Чем заполнить |
|---|---|
| `APP_SECRET_KEY` | Случайная строка. Сгенерировать: `python -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `APP_BOOTSTRAP_OPERATOR_PASSWORD` | Пароль первого оператора. Не короче 8 символов, не длиннее 72 байт |

Необязательные:

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `APP_BOOTSTRAP_OPERATOR_LOGIN` | `operator` | Логин первого оператора |
| `APP_ACCESS_TOKEN_TTL_MINUTES` | `720` | Срок действия токена, минут |
| `APP_BCRYPT_ROUNDS` | `12` | Стойкость хеширования. Ниже 12 не опускать |
| `APP_CORS_ORIGINS` | пусто | Нужно, только если фронтенд вынесут на отдельный домен |

`PORT` Railway подставляет сам — задавать не нужно.

### 4. Первый запуск

При старте приложение накатывает миграции Alembic, заливает матрицу из ТЗ (61 правило,
16 способов) и, если пользователей ещё нет, создаёт учётную запись оператора.

Проверить: `https://<домен>/api/health` должен вернуть `{"status":"ok"}`.

### 5. Сразу после первого входа

1. Войти оператором и **сменить пароль**: раздел «Пользователи».
2. Завести муниципальные образования.
3. Завести учётные записи специалистов и методолога.

`APP_BOOTSTRAP_OPERATOR_PASSWORD` действует только при создании учётной записи на пустой базе;
позже изменение переменной пароль не поменяет.

## Проверка перед заливкой

Образ собирается и проверяется локально ровно в том виде, в каком пойдёт на платформу:

```bash
docker build -t portal:railway .

docker run -d --name portal-pg -e POSTGRES_PASSWORD=pg -e POSTGRES_USER=pg \
  -e POSTGRES_DB=portal postgres:16-alpine

docker run --rm --link portal-pg:db -p 8090:8090 \
  -e PORT=8090 \
  -e DATABASE_URL="postgres://pg:pg@db:5432/portal" \
  -e APP_SECRET_KEY="$(python -c 'import secrets;print(secrets.token_urlsafe(48))')" \
  -e APP_BOOTSTRAP_OPERATOR_PASSWORD="Demo-Portal-2026" \
  portal:railway
```

Портал будет на <http://localhost:8090>. Размер образа — около 270 МБ.

## Если что-то пошло не так

| Признак | Причина |
|---|---|
| В логах «Не заданы обязательные переменные окружения» | Не задан `APP_SECRET_KEY` или `APP_BOOTSTRAP_OPERATOR_PASSWORD` |
| `ModuleNotFoundError: psycopg2` | Строка подключения пришла в неизвестном формате — проверьте `DATABASE_URL` |
| В логах «Не задана база данных» | База не привязана к службе: добавьте `DATABASE_URL = ${{Postgres.DATABASE_URL}}` |
| Проверка состояния не проходит | Служба не видит базу: привяжите `DATABASE_URL` в Variables |
| Протокол выгружается только в .docx | В образе нет шрифта с кириллицей. `Dockerfile` ставит `fonts-dejavu-core` — проверьте, что сборка шла по корневому `Dockerfile` |
| Вход перестаёт работать после передеплоя | `APP_SECRET_KEY` меняется между запусками — задайте его переменной, а не генерируйте при старте |

## Чего на платформе нет

Файлы протоколов хранятся в PostgreSQL, а не на диске, — отдельный том не нужен и при
перезапуске службы ничего не теряется.

Резервное копирование базы остаётся за платформой: срок хранения решений по ответу № 6
опросника — постоянный, поэтому снимки базы обязательны.
